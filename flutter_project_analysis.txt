1. SUMMARY
================================================================================

PROJECT OVERVIEW
----------------
Banco Douro is a Flutter mobile banking application implementing account
management and transaction processing with local (SQLite) and remote (HTTP REST)
data persistence. The app follows an MVVM-style architecture with separation
between models, services, repositories, viewmodels, and UI layers.

STRENGTHS
---------
- Clean separation of concerns with layered architecture
- Proper use of Dart idioms (factory constructors, copyWith patterns)
- Local database integration with SQLite for offline support
- Custom exception classes for business logic errors
- Type-safe model classes with JSON serialization
- Stream-based logging in services

WEAKNESSES
----------
- Critical security vulnerabilities (HTTP, debug signing, weak IDs)
- Error handling is commented out or missing throughout
- 0% test coverage (only boilerplate test exists)
- Hardcoded configuration values (URLs, delays, account types)
- Memory leaks (unclosed StreamController)
- No input validation in UI or services
- No state management framework
- Missing accessibility features

2.1 BUGS AND ERRORS
--------------------------------------------------------------------------------

CRITICAL BUGS
-------------

[C01] Commented Out Error Handling
     File: lib/services/account_service.dart:23-45
     Description: All try-catch blocks are commented out. Network failures,
     JSON parsing errors, or invalid responses will crash the app.
     Impact: App crashes on any network issue.

[C02] StreamController Memory Leak
     File: lib/services/account_service.dart:10-11
     Description: StreamController is created but never closed. No dispose()
     method exists. Every instance of AccountService leaks memory.
     Impact: Memory leak, potential app crashes.

[C03] Hardcoded Account Type in Repository
     File: lib/data/repositories/account_local_repository.dart:82
     Description: Account type is hardcoded as 'x' instead of using
     account.accountType. All account types are lost when saving locally.
     Impact: Data corruption, tax calculations will fail.
     Code: 'account_type': 'x',  // Should be: account.accountType

[C04] Weak Transaction ID Generation
     File: lib/services/transaction_service.dart:64
     Description: Uses Random().nextInt(89999) + 10000 for transaction IDs.
     Only 90,000 possible values, high collision risk, not cryptographically
     secure.
     Impact: Transaction ID collisions, security vulnerability.
     Fix: Use uuid package: const Uuid().v4()

[C05] HTTP Response Not Validated
     File: lib/services/transaction_service.dart:77
     Description: response.body decoded without checking HTTP status code.
     Invalid responses will throw uncaught exceptions.
     Impact: App crashes on server errors.

[C06] No Error Handling in addTransaction
     File: lib/services/transaction_service.dart:92-97
     Description: POST request has no error handling, status code validation,
     or timeout. Network errors crash the application silently.
     Impact: Silent failures, app crashes.

[C07] Async Operation in Constructor
     File: lib/ui/home_screen.dart:20-22
     Description: _HomeScreenState constructor calls refreshGetAll() which is
     async. Constructors should not perform async operations.
     Impact: Race conditions, state accessed before initialization.
     Fix: Move to initState() method.

[C08] Missing Return Type in dispose()
     File: lib/ui/widgets/add_account_modal.dart:163-168
     Description: dispose() method missing void return type.
     Code: dispose() { ... }  // Should be: void dispose() { ... }
     Impact: Lifecycle management issues.

HIGH SEVERITY BUGS
------------------

[H01] Incorrect Status Code Validation
     File: lib/services/account_service.dart:55
     Description: Uses response.statusCode.toString()[0] == "2" which is
     fragile string manipulation instead of numeric comparison.
     Fix: Use response.statusCode >= 200 && response.statusCode < 300

[H02] Missing HTTP Timeout
     File: lib/services/account_service.dart:26
     Description: No timeout on HTTP GET request. App could hang indefinitely.
     Fix: Add .timeout(Duration(seconds: 30))

[H03] Hardcoded isOnline Flag
     File: lib/viewmodels/account_viewmodel.dart:9

     Impact: Offline-first architecture is non-functional.

[H04] Unsafe Type Cast in Repository
     File: lib/data/repositories/account_local_repository.dart:91
     Description: (map['balance'] as num).toDouble() fails if balance is

[H05] Double List Traversal
     File: lib/services/transaction_service.dart:23-37
     Description: Uses .where().isEmpty then .firstWhere() - searches list
     twice unnecessarily.
     Impact: O(2n) instead of O(n) performance.

[H06] Inefficient List Index Operations
     File: lib/services/transaction_service.dart:55-61
     Description: Uses indexWhere() twice to update list elements.
     Impact: Unnecessary list traversals.

[H07] No Error Handling in refreshGetAll

     Description: No try-catch. Exceptions propagate and crash the app.

[H08] ListView Without Keys
     File: lib/ui/home_screen.dart:67-73
     Description: AccountWidget items created without keys. Causes state
     preservation issues when list changes.
     Fix: Add key: ValueKey(account.id)

[H09] No Input Validation in Login
     File: lib/ui/login_screen.dart:36-62
     Description: Email and password fields have no validation. Login doesn't
     actually authenticate - just navigates.
     Impact: Security vulnerability, no user feedback.

[H10] setState After Dispose Risk
     File: lib/ui/widgets/add_account_modal.dart:136-157
     Description: After async addAccount(), closeModal() is called but widget
     may be disposed. setState on disposed widget causes errors.
     Fix: Add if (mounted) check before closeModal()
