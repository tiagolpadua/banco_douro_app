# Copilot Instructions for Banco Douro App

## Project Overview
This is a Flutter application for Banco Douro. The app manages accounts and transactions with a clean architecture pattern.

## Architecture & Code Style

### Directory Structure
- `lib/main.dart` - Application entry point
- `lib/models/` - Data models (Account, Transaction, AccountType)
- `lib/services/` - API communication and business logic
- `lib/viewmodels/` - State management and view logic
- `lib/ui/` - UI screens and widgets
- `lib/data/` - Database and repository layer
- `lib/exceptions/` - Custom exception classes
- `lib/helpers/` - Utility helper functions

### Naming Conventions
- **Files**: Use snake_case (e.g., `account_service.dart`)
- **Classes**: Use PascalCase (e.g., `AccountViewModel`)
- **Methods/Variables**: Use camelCase (e.g., `getAccountList()`)
- **Constants**: Use camelCase (e.g., `const double defaultPadding = 16.0`)

### Flutter Best Practices
- Use StatelessWidget for simple UI components without state
- Use StatefulWidget only when necessary
- Prefer composition over inheritance
- Keep widgets small and focused on a single responsibility
- Use const constructors when possible
- Follow Material Design guidelines

## Code Generation & Dependencies
- Uses `pubspec.yaml` for dependency management
- Run `flutter pub get` after adding new dependencies
- Ensure Android and iOS native dependencies are properly configured in build files

## Model Structure
Models should be simple data classes:
```dart
class Example {
  final int id;
  final String name;
  
  Example({
    required this.id,
    required this.name,
  });
  
  factory Example.fromJson(Map<String, dynamic> json) {
    return Example(
      id: json['id'],
      name: json['name'],
    );
  }
  
  Map<String, dynamic> toJson() => {
    'id': id,
    'name': name,
  };
}
```

## Service Layer
- Services handle API calls and business logic
- Use `http_interceptors.dart` for HTTP interceptors
- Implement proper error handling and exceptions
- Methods should be async where applicable

## ViewModel Pattern
- ViewModels manage state for UI
- Separate presentation logic from UI logic
- Use notifiers or state management solution for reactive updates
- Keep ViewModels testable by avoiding direct widget references

## UI Development
- Follow Mobile-first responsive design
- Use `lib/ui/styles/` for theme and styling
- Create reusable widget components in `lib/ui/widgets/`
- Keep screens focused on layout and user interaction

## Database
- Use SQLite via sqflite plugin
- Database operations should be in `lib/data/database/`
- Repository pattern for data access

## Error Handling
- Use custom exceptions from `lib/exceptions/`
- Implement proper try-catch blocks
- Provide meaningful error messages to users

## Testing
- Unit tests in `test/` directory
- Test services, viewmodels, and models
- Use mocking for external dependencies
- Widget tests for UI components

## Git Workflow
- Create feature branches for new features
- Use clear commit messages
- Keep commits atomic and focused
- Submit pull requests for code review before merging to main

## Important Notes
- Always run `flutter analyze` before committing
- Format code with `flutter format .`
- Test changes on both Android and iOS platforms
- Keep dependencies up to date
